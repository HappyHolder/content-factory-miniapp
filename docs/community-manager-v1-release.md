# Publium Community Manager v1 — реализация

Дата: 2026-07-14
Статус: реализовано, production rollout

## Что вошло

- стандартный shared Telegram executor и персональный CM-бот для каждого сообщества;
- переменные token, username и отдельный webhook secret;
- установка webhook отдельной npm-командой;
- связь с существующим Community и группой Moderator;
- конфигурация с draft/apply версиями;
- единый понятный рабочий режим: запущен или на паузе; технические Observe/Drafts скрыты и отключены;
- настраиваемая личность, тон, обращение и запреты;
- ответы на reply, mention и вопросы о продукте;
- краткосрочный контекст ветки;
- grounded support по BrandKit, ProjectDoc и подтверждённому FAQ;
- web research через существующий researchEngine;
- источники сохраняются только во внутреннем журнале владельца и не публикуются в чат;
- quiet hours, per-user cooldown, часовые/суточные лимиты и research budget;
- durable PostgreSQL queue с lease/retry/recovery;
- задержка и проверка Moderator events перед AI-ответом;
- повторная проверка pause непосредственно перед отправкой;
- симулятор решения;
- журнал ответов, молчания, drafts, activity, ошибок, latency и токенов;
- ручные discussion, Telegram poll и digest;
- 24-часовой retention сырого текста;
- каскадное удаление CM-данных вместе с Community;
- mobile UI внутри существующей вкладки Community Manager.

## Безопасные значения по умолчанию

- первый запуск выполняется только после явного «Применить»; далее CM работает в Autopilot или находится на паузе;
- ambient conversation: off;
- research: when needed;
- proactive automation: off;
- quiet hours: 23:00–09:00 Europe/Moscow;
- максимум 20 ответов/час и 100/сутки;
- CM не имеет функций mute/delete/ban;
- при сбое AI или недостатке контекста отправка не выполняется;
- отключённый формат highlight не генерируется.

## Production env

- COMMUNITY_MANAGER_BOT_TOKEN
- COMMUNITY_MANAGER_BOT_USERNAME
- COMMUNITY_MANAGER_WEBHOOK_SECRET

Secret генерируется во время rollout и не передаётся пользователю. Compose передаёт все три значения только API-контейнеру.

## Операции

Установить webhook:

    docker compose exec api npm run set-community-manager-webhook

Проверить API:

    docker compose ps
    docker compose logs --tail=100 api

Webhook endpoint:

    https://publium.ru/api/community-manager/webhook

## Ограничение v1

Отдельные пользовательские аккаунты-персонажи реализуются следующим этапом поверх этого runtime. В v1 публично пишет один CM bot. Discussion, poll и digest запускаются владельцем из интерфейса; автоматический календарь событий входит в следующий этап.

## Исправление Telegram-сессии — 2026-07-14

- обмен `initData` на защищённую сессию Moderator/CM приведён к общему 24-часовому окну Telegram-авторизации Publium;
- устранена ошибка `initData has expired`, возникавшая при открытии Community спустя 10 минут после запуска Mini App;
- если истекла уже сама 24-часовая Telegram-сессия, интерфейс показывает понятную инструкцию полностью закрыть и заново открыть Publium через бота.

## Улучшение CM после первого теста — 2026-07-14

По результатам теста в `Test Publium Chat` исправлены поведение и интерфейс:

- убраны пользовательские переключатели «Наблюдать / Черновики / Автопилот»; в интерфейсе остались однозначные состояния «Запустить» и «Поставить на паузу»;
- шапка показывает привязанную группу и отдельную карточку бота-исполнителя;
- на главной карточке и каждой секции добавлена контекстная справка со сценарием работы;
- доступен выбор стандартного `@Publium_CM_Bot` либо создание персонального CM-бота с собственными именем, username и аватаром;
- персональный бот создаётся через Telegram Bot Management Mode: Publium получает токен автоматически, шифрует его AES-GCM и самостоятельно настраивает отдельный secret webhook;
- персонального бота необходимо добавить администратором связанной группы; это проверяется перед активацией;
- быстрые последовательные сообщения одного участника объединяются в один смысловой запрос и получают один ответ;
- cooldown теперь отсчитывается от последнего реально отправленного ответа;
- обычный ответ ограничен 2–5 короткими предложениями и примерно 900 символами;
- заголовки, Markdown-маркеры и отключённая подсветка очищаются до отправки в Telegram;
- интернет-ресерч запускается только для актуальных данных: новостей, цен, релизов и текущих событий, а не для базовых объяснений;
- режим участия в обычной беседе по умолчанию выключен, чтобы CM отвечал на прямые обращения и содержательные вопросы, а не на каждую реплику.

### Production rollout этого обновления

Новых env-переменных для персональных CM-ботов не требуется. Используются существующие `TELEGRAM_BOT_TOKEN`, `MANAGED_BOT_ENCRYPTION_KEY`, `PUBLIC_BASE_URL` и shared CM env. Миграция создаёт `ManagedCommunityManagerBot`, добавляет `executorType` и переводит старые CM в `AUTOPILOT` без автоматического включения выключенных менеджеров.

Обычный деплой:

    ssh root@45.146.165.97 "cd /opt/publium && git pull origin main && cd deploy && docker compose up -d --build"

Миграции применяются автоматически на старте API. После деплоя проверить:

    ssh root@45.146.165.97 "cd /opt/publium/deploy && docker compose ps && docker compose logs --tail=100 api"

## Управляемые источники интернет-ресерча — 2026-07-14

- в карточке «Интернет-ресерч» добавлена отдельная настройка источников: строгий список разрешённых доменов либо весь интернет с исключениями;
- безопасный режим по умолчанию — строгий список. Пустой список означает, что CM не ищет по случайным сайтам и не выдумывает актуальные данные;
- YouTube, видеоплатформы и социальные сети заблокированы по умолчанию; запрещённый домен всегда имеет приоритет над разрешённым;
- ограничения применяются на стороне Serper, Tavily и Anthropic, затем результаты повторно фильтруются локально до передачи текста модели;
- ссылки и названия источников не публикуются и не рекомендуются участникам. Они сохраняются только в техническом журнале владельца для проверки ответа;
- если подтвердить цену, новость или другое актуальное значение по доверенным источникам не удалось, CM прямо сообщает, что подтверждения нет, и не называет число;
- владелец настраивает максимум поисков на один ответ и суточный лимит ресерча.
## Автоматическое оживление чата — 2026-07-14

- добавлен отдельный фоновый планировщик Community Manager с проверкой активных сообществ раз в 7 минут;
- автоматический режим включается владельцем в карточке «Активности» и не влияет на ручные кнопки запуска;
- первая инициатива возможна после 60 минут без сообщений участников; период тишины настраивается от 15 минут;
- доступны тематическое обсуждение, Telegram-опрос, мини-игра или прогноз и краткий дайджест;
- генератор учитывает документы проекта, недавнюю беседу и последние активности, не спрашивает «почему молчим» и не повторяет недавние механики;
- безопасные значения по умолчанию: не более одной автоматической инициативы в сутки и трёх в неделю, минимальная пауза 24 часа, тихие часы соблюдаются;
- реакция оценивается по сообщениям участников в настраиваемом окне после активности;
- после одной проигнорированной попытки пауза составляет минимум 24 часа, после двух — 72 часа, после трёх — 7 дней;
- состояние и результат активности сохраняются в PostgreSQL, поэтому перезапуск API не сбрасывает антиспам-логику;
- ввод доменов для интернет-ресерча теперь принимает перенос строки, запятую и точку с запятой; сохраняется только домен без URL страницы.
## Вариативность Moderator и выборочное участие CM — 2026-07-14

- Moderator учитывает пять последних вмешательств за сутки и получает прямой запрет повторять их формулировки и структуру;
- устранено сокращение настроенного cooldown до 60 секунд после первого вмешательства: применяется полный интервал из конфигурации;
- повторный участник определяется по автору текущего сообщения даже при конфликте нескольких людей;
- если повторное нарушение приводит к предупреждению, Moderator не дублирует его дополнительным нравоучением;
- Community Manager получил выборочное участие в обычной беседе: содержательные вопросы, обратная связь и подходящие реплики проходят отдельную policy-проверку;
- короткий смех, шум, небезопасные сообщения и слабоуверенные решения не вызывают ответ;
- общий cooldown обычной беседы действует на весь чат и настраивается в карточке «Ответы и лимиты»; прямые reply, упоминания и поддержка продолжают работать независимо;
- для `Test Publium Chat` выборочное участие CM и автоматическое оживление чата включаются при production rollout этого обновления.

## Естественная речь Community Manager — 2026-07-14

- контекст ответа теперь включает не только последние сообщения участников, но и последние ответы самого CM, чтобы он не начинал разговор заново и не повторялся;
- приветствие разрешено только при реальном первом обращении, если сам пользователь начал с приветствия; в продолжающемся чате повторные приветствия запрещены;
- из речевого поведения исключены самопрезентация и саппорт-штампы вроде «давай разбираться», «что именно интересует», «пиши — посмотрим» и «рад помочь»;
- короткие реплики, шутки и подтверждения получают соразмерный короткий ответ без принудительного возврата к тематике канала;
- если модель всё же создаёт шаблонный саппорт-ответ, он автоматически отправляется на одну естественную переформулировку перед публикацией;

## Комплексное усиление CM и Moderator — 2026-07-14

### 1. Стабилизация runtime

- перед повторной обработкой job проверяется уже выполненная доставка этого `messageId`; завершённый ответ повторно в Telegram не отправляется;
- ошибки AI и Telegram получают максимум три попытки с экспоненциальной паузой 15/30 секунд вместо одинакового немедленного повтора;
- health API показывает очередь, число retry, ошибки за 24 часа, возраст старейшей задачи, последнее успешное состояние и последнюю ошибку;
- просроченные lease по-прежнему возвращаются в очередь, а после исчерпания попыток задача остаётся в `FAILED` для диагностики.

### 2. Прозрачность решений для владельца

- журнал в Mini App показывает русские статусы и причины: ответ, осознанное молчание, активность, черновик или ошибка;
- в сводке видны очередь, retry и ошибки за сутки; карточка раскрывает уверенность, задержку, расход токенов и итоговый текст;
- использованные домены интернет-ресерча доступны только владельцу внутри раскрытой карточки;
- в Telegram-чат не публикуются журнал, причины решений, ссылки, источники или технические данные — участники получают только итоговое сообщение CM.

### 3. Разговорная модель

- прямой reply больше не считается безусловной командой ответить: классификатор может естественно промолчать на смех, благодарность, подтверждение или реплику без продолжения;
- часовой контекст различает участников стабильными псевдонимами и содержит до 16 последних сообщений;
- при reply CM получает точный текст собственного сообщения, на которое отвечает участник;
- prompt version повышена до `community-manager-conversation-v4`; сохраняются запрет повторных приветствий, саппорт-штампов, навязчивого возврата к теме канала и автоматическая переформулировка неестественного черновика.

### 4. Знания и support

- документы режутся на перекрывающиеся смысловые фрагменты, включая длинные разделы;
- результаты FAQ и документов ранжируются по покрытию запроса, точной фразе, совпадению с названием источника и приоритету подтверждённого FAQ;
- в prompt передаются только пять наиболее релевантных фрагментов; проектные знания и внешний ресерч остаются раздельными;
- при отсутствии подтверждённых свежих данных CM не выдумывает число или факт и использует настроенную эскалацию.

### 5. Проактивность

- автоматический планировщик учитывает результат прошлых механик: успешные форматы получают больший вес, проигнорированные — меньший;
- подряд не запускается один и тот же тип активности, если доступна альтернатива;
- темы выбираются без недавних повторов вместо механического прохода по индексу;
- действующие quiet hours, дневные/недельные лимиты и backoff 24 часа / 72 часа / 7 дней сохранены.

### 6. Moderator

- решение интервенции получило уровень тяжести `low / medium / high` и сведения о подтверждённых нарушениях участника за семь дней;
- prompt требует наименее жёсткое достаточное действие и запрещает искусственный редирект к BTC, крипте или теме канала;
- ответ проверяется на смысловое сходство с пятью последними вмешательствами и на шаблонный тематический редирект;
- если модель повторилась или сгенерировала неуместный шаблон, выбирается короткая вариативная реплика по категории нарушения;
- в журнал Moderator записываются тяжесть, история нарушений, участники, санкция и фактический текст вмешательства; prompt version повышена до `moderator-intervention-v3`.
