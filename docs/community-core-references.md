# Ядро комьюнити — референсы по созданию человечных AI-личностей

Статус: справочный материал для проектирования «Ядра комьюнити».
Дата ресёрча: 2026-07-16.

Ядро комьюнити — отдельный продукт (таб рядом с Moderator и Community Manager):
владелец подключает свои запасные Telegram-аккаунты, каждый становится
устойчивой AI-личностью, которая автономно живёт в чате канала. Личность — это
просто человек, который общается; без опросов, ивентов и целей CM.

## 1. Character Card V2 — стандарт описания личности

Открытый де-факто стандарт карточек персонажей (SillyTavern и десятки платформ):
<https://github.com/malfoyslastname/character-card-spec-v2>

Ключевые поля: `name`, `description`, `personality` (черты), `scenario`,
`first_mes`, **`mes_example`** и **`character_book`**.

Что берём:

- **Примеры реплик (`mes_example`) — главное поле голоса.** 3–5 реальных
  сообщений персонажа задают стиль сильнее любых прилагательных. Обязательное
  поле нашего редактора личности.
- **Лорбук (`character_book`)** — канон-факты с триггерами по ключевым словам:
  упомянули тему → факт подтягивается в контекст. Это готовый паттерн для
  нашего `PersonaCanonFact` (биография как структурированный канон; модель не
  выдумывает факты о себе).
- Совместимость структуры карточки с V2 — сможем импортировать готовые карточки.

## 2. Stanford Generative Agents («Smallville») — научная база

«Generative Agents: Interactive Simulacra of Human Behavior»:
<https://ar5iv.labs.arxiv.org/html/2304.03442>

25 автономных агентов жили в виртуальном городке, вели распорядок, заводили
знакомства и сами организовали вечеринку. Главный вывод: **правдоподобность
даёт не размер модели, а архитектура памяти**.

Три компонента:

1. **Memory stream** — лента наблюдений на естественном языке; выборка по
   сумме свежести (экспоненциальный спад) + важности (оценка LLM) +
   релевантности (эмбеддинги).
2. **Reflection** — периодический синтез наблюдений в выводы более высокого
   уровня («Стас часто спорит про L2 → он максималист»), выводы возвращаются
   в память.
3. **Planning / распорядок** — у агента есть ритм дня.

Что берём:

- memory stream + reflection на каждую личность (наблюдения из чата, выводы об
  участниках и темах);
- **ритм присутствия**: личность «онлайн» в свои часы, а не 24/7 — мгновенно
  снижает ощущение бота.

## 3. Kindroid / Nomi — коммерческий эталон компаньонов

Kindroid memory: <https://kindroid.ai/docs/article/memory/>,
персонализация: <https://kindroid.ai/docs/article/customizing-personality/>

- Память трёх слоёв: **persistent** (бэкстори, ключевые воспоминания, примеры
  реплик, директивы), **journal** (записи с ключевыми фразами-триггерами — тот
  же лорбук), **long-term** (автоконсолидация из переписки).
- ~47 параметров личности; «flairs» — режимы интерпретации бэкстори.
- **Dynamism** — ползунок хаотичности/вариативности речи.

Что берём: трёхслойную модель памяти; ползунок «dynamism» в редакторе.

## 4. Human-like Telegram-боты — приёмы живой подачи

<https://github.com/emqnuele/humanlike-telegram-bot> и разбор
<https://medium.com/@incapablepolygon/writing-a-llm-based-telegram-bot-that-texts-like-a-person-would-944853849075>

- **Разбивка ответа на несколько коротких сообщений** — люди не пишут абзацами;
  промту: «пиши как в переписке с другом, отдельные мысли — отдельными
  сообщениями».
- **Динамическая задержка**: `len(text) / chars_per_second * random_variance` +
  статус «печатает…» на время задержки.
- Случайный разброс пауз между сообщениями — ничего идеально ровного.

Что берём целиком: формула задержек, разбивка, «печатает…», случайность.

## 5. Сводка: поля редактора личности

- Идентичность: имя, пол, возраст, город, профессия, аватар.
- Голос: 3–5 примеров реплик, манера, сленг, эмодзи, длина сообщений, dynamism.
- Канон-факты (лорбук с триггерами): биография, опыт, отношения к темам.
- Роль/характер: заводила, скептик, эксперт по теме X, шутник, новичок.
- Поведение: во что вступает, о чём молчит, запретные темы, границы.
- Ритм жизни: часы присутствия, плотность участия.
- Память: memory stream + reflection.
- Подача: мультисообщения + typing-задержки со случайностью.
- AI-черновик канона по короткому вводу («крипто-скептик, 30, Питер») с ручной
  правкой.

## 6. Зафиксированные архитектурные решения (2026-07-16)

- Ядро комьюнити — **отдельный продукт и отдельный модуль**; код CM не
  трогается вообще (общие только read-only: Community, Channel, BrandKit,
  документы).
- Личности **полностью автономны**: каждая читает чат через собственную
  MTProto-сессию своего аккаунта, сама анализирует и сама решает, писать или
  молчать. Центрального оркестратора нет.
- Дубли исключаются естественно: личность видит ответы других (включая
  AI-коллег) как обычный контекст чата + атомарная отметка в БД «на сообщение
  уже отвечают» против гонки в одну секунду.
- Генерация — GPT-5.6 Terra через существующий `replicateText`.
- Только реальные user-аккаунты владельца (никаких bot-персонажей); вход
  номер → код → 2FA внутри мини-аппа; сессии шифруются AES-GCM по паттерну
  managed-ботов; в профиле аккаунта — маркировка AI-личности.
- **Личности ставят реакции** — людям и другим личностям. Решение о реакции —
  часть того же единственного прохода Terra (молчать / реакция / ответ /
  реакция+ответ), дополнительных AI-затрат нет. Выбор эмодзи — из характера и
  интересов (скептик 🤔, заводила 🔥, шутник 😂) и списка разрешённых реакций
  группы. Естественность: реакция не на всё подряд (доля рандомизирована),
  лимиты выше чем на сообщения, задержка «прочитал — потом лайкнул», запрет
  хоровых реакций всех личностей на одно сообщение. Всё в журнал.
